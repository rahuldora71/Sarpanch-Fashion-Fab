# Sarpanch Fashion Fab (SFF) — Backend ERP

Sarpanch Fashion Fab Tailoring ERP backend built with Spring Boot, Java, and Spring Security.

---

## Meta WhatsApp Cloud API Webhook Integration

This application implements production-ready, secure webhooks for the **Meta WhatsApp Business Platform / WhatsApp Cloud API**.

### Webhook Endpoints

| Method | Endpoint | Purpose | Authentication |
|---|---|---|---|
| `GET` | `/api/whatsapp/webhook` | Webhook verification handshake with Meta | Verification Token (`hub.verify_token`) |
| `POST` | `/api/whatsapp/webhook` | Ingests WhatsApp messages & status events | Cryptographic HMAC-SHA256 signature (`X-Hub-Signature-256`) |

## 1. Environment Variables & Configuration

The application reads configuration from environment variables or Spring configuration properties (`application-dev.properties`):

| Property | Environment Variable | Description | Example / Placeholder |
|---|---|---|---|
| `whatsapp.verify-token` | `WHATSAPP_VERIFY_TOKEN` | Secret token shared with Meta for the GET verification challenge | `your_webhook_verification_token` |
| `whatsapp.app-secret` | `WHATSAPP_APP_SECRET` | Meta App Secret from Meta Developer Dashboard (used for HMAC-SHA256 signature validation) | `your_meta_app_secret_here` |
| `whatsapp.access-token` | `WHATSAPP_ACCESS_TOKEN` | System User or Permanent Access Token for Cloud API calls | `your_system_user_access_token` |
| `whatsapp.phone-number-id` | `WHATSAPP_PHONE_NUMBER_ID` | WhatsApp Business Phone Number ID from Meta Dashboard | `109876543210987` |
| `whatsapp.api-version` | `WHATSAPP_API_VERSION` | Meta Graph API Version | `v21.0` |

### Setting Environment Variables in Windows PowerShell (Local Development)

```powershell
$env:WHATSAPP_VERIFY_TOKEN="my_sff_secure_webhook_token_2026"
$env:WHATSAPP_APP_SECRET="0123456789abcdef0123456789abcdef"
$env:WHATSAPP_PHONE_NUMBER_ID="109876543210987"
$env:WHATSAPP_ACCESS_TOKEN="EAA..."
$env:WHATSAPP_API_VERSION="v21.0"
```

### Production Hosting Configuration

In production environments (e.g., Docker, AWS ECS, Kubernetes, systemd):
- Store `WHATSAPP_APP_SECRET` and `WHATSAPP_ACCESS_TOKEN` in a secure secrets manager (AWS Secrets Manager, HashiCorp Vault, or encrypted environment variables).
- Never commit secrets to Git or expose them in client-side code.

## 2. Local Development & HTTPS Testing with Meta (Step-by-Step)

Meta requires a publicly accessible HTTPS callback URL to verify and deliver webhook events. Since the local backend runs at `http://localhost:8082`, use a temporary HTTPS tunnel (e.g., ngrok, Cloudflare Tunnel, or localtunnel) during development.

### Step 1: Start the Spring Boot Backend
Ensure the backend is running locally on port `8082`:
```powershell
.\mvnw.cmd spring-boot:run
```
*(Or launch `AuthAppApplication` directly in your IDE).*

### Step 2: Start an HTTPS Tunnel to Port 8082
In a separate terminal, launch your HTTPS tunnel pointing to `8082`:
```bash
ngrok http 8082
```

### Step 3: Copy the Temporary HTTPS Tunnel URL
The tunnel tool will provide an active HTTPS forwarding URL, for example:
```text
Forwarding https://<your-subdomain>.ngrok-free.app -> http://localhost:8082
```
> [!IMPORTANT]
> Use the actual HTTPS URL generated by your tunnel. Temporary tunnel URLs change each time the tunnel is restarted. For production, configure a stable custom domain with a valid SSL/TLS certificate.

### Step 4: Construct the Callback URL
Append `/api/whatsapp/webhook` to your HTTPS tunnel URL:
```text
https://<your-subdomain>.ngrok-free.app/api/whatsapp/webhook
```

### Step 5: Configure the Webhook in Meta App Dashboard
1. Go to the [Meta App Dashboard](https://developers.facebook.com/apps/).
2. Select your App > **WhatsApp** > **Configuration**.
3. Under **Webhook**, click **Edit**.
4. In **Callback URL**, enter your full HTTPS URL:
   `https://<your-subdomain>.ngrok-free.app/api/whatsapp/webhook`
5. In **Verify Token**, enter the exact string configured in your `WHATSAPP_VERIFY_TOKEN` environment variable.
6. Click **Verify and Save**.
7. Meta will send a GET request to `/api/whatsapp/webhook` with `hub.mode=subscribe`, `hub.verify_token`, and `hub.challenge`. The backend will validate the token in constant-time and return the challenge with HTTP 200.

### Step 6: Subscribe to Webhook Fields
1. After verification succeeds, click **Manage** under Webhook fields.
2. Subscribe to the **`messages`** field (this delivers both customer incoming messages and delivery status updates: sent, delivered, read, failed).
3. Confirm the relevant WhatsApp Business Phone Number ID in your dashboard.

### Step 7: Inspect Server Logs Safely
When Meta delivers test events or customer interactions, safe logs will appear in your application console:
```text
INFO ... Meta WhatsApp webhook verification handshake succeeded.
INFO ... Accepted incoming WhatsApp customer message [type: text] (wamid: wamid....)
INFO ... Updated MessageLog ID 42 status from 'SENT' to 'DELIVERED'
```
*(Sensitive data like message bodies, phone numbers, and secrets are masked or excluded from logs for customer privacy).*

## 3. Security & Architecture Details

1. **GET Verification**:
   - Compares `hub.verify_token` against `whatsapp.verify-token` using `MessageDigest.isEqual(...)` for constant-time comparison, protecting against timing attacks.
   - Requires `hub.mode=subscribe`.
   - Returns HTTP 200 with `hub.challenge` as plain text on match; HTTP 403 on failure.

2. **POST Cryptographic Signature Validation**:
   - Meta calculates an HMAC-SHA256 signature using your Meta App Secret across the raw request body bytes and sends it in the `X-Hub-Signature-256` header (`sha256=<hex>`).
   - The backend validates the signature on the unmodified byte array before JSON parsing.
   - Missing, malformed, or incorrect signatures return HTTP 401 Unauthorized immediately.
   - If `WHATSAPP_APP_SECRET` is not set, requests fail securely (HTTP 401).

3. **Idempotency & Deduplication**:
   - Meta guarantees at-least-once delivery and may retry webhook requests for up to 7 days.
   - Incoming events are tracked in `whatsapp_webhook_events` with unique constraint `uk_wa_wamid_status` on `(provider_message_id, status)`.
   - Repeated webhook deliveries are safely recognized and acknowledged with HTTP 200 without creating duplicate database records or re-triggering business operations.

4. **Out-of-Order Status Protection**:
   - Delivery notifications can arrive out of order (e.g. `read` before `delivered`).
   - A monotonic status hierarchy (`SENT` < `DELIVERED` < `READ`/`CLICKED`) ensures a message marked `READ` is never downgraded to `DELIVERED` by a delayed webhook retry.

5. **Spring Security Scope**:
   - Only `/api/whatsapp/webhook` is exempted from staff JWT authentication to permit Meta's handshake and callbacks.
   - All other shop operations (orders, billing, payments, staff endpoints) remain strictly protected by JWT and role-based permissions.
